너는 이 저장소의 1번 개발자다. Next.js App Router + TypeScript + Tailwind CSS 음악 플레이리스트 앱의 화면과 사용자 기능을 실제 구현해라.

먼저 AGENTS.md, docs/contracts.md, types/music.ts와 기존 코드를 읽고 아래 경계를 지켜라.

[파일 소유권 — 반드시 준수]
- 생성·수정·삭제 가능: app/**, components/**, public/**만.
- 읽기·import만 가능: types/**, data/**, lib/**, tests/** 및 모든 공동 파일.
- 수정 금지: AGENTS.md, README.md, docs/**, package.json, lock 파일, tsconfig, Next.js·Tailwind·PostCSS·테스트 설정 등 루트 파일.
- 다른 개발자의 변경을 되돌리거나 이동·포맷하지 마라. 전체 자동 수정과 프로젝트 재생성을 하지 마라.
- 의존성 추가나 공통 계약 변경이 필요하면 정확한 요구 사항을 보고하되 직접 변경하지 마라.
- 초기 설정이 없어도 담당 UI 파일은 구현하고 실행 검증이 불가능한 이유를 보고해라.

[구현]
1. app/layout.tsx, app/page.tsx, app/globals.css와 필요한 components를 작성한다.
2. 한국어 반응형 UI로 가수·장르·연도·분위기 생성 방식을 선택하게 한다. 조건 선택지는 songs 데이터에서 추출한다.
3. 생성 곡 수는 5~30곡, 기본 10곡. 새로운 곡 비율은 0~100% 슬라이더, 기본 50%. 새로운 곡은 isKnown=false인 샘플 곡이라는 안내를 제공한다.
4. generatePlaylist를 호출해 결과와 실제 새 곡 비율, warnings를 표시한다. 곡 제목·가수·장르·연도·분위기·새로운 곡 여부를 표시한다.
5. 전체 샘플 데이터에서 제목·가수로 검색해 추가한다. ID 중복 추가를 막고 결과에서 곡을 제거할 수 있게 한다.
6. 생성 직후 및 사용자 추가·제거 시 savePlaylist로 자동 저장한다. 저장된 목록 조회·선택과 변경 내역 표시를 구현한다.
7. crypto.randomUUID()로 플레이리스트와 변경 ID를 생성하고 ISO 시각을 사용한다. 생성 직후 changes는 빈 배열이다. 추가·제거 시 action, songId, timestamp를 기록한다.
8. loadPlaylists는 마운트 후 호출한다. 초기 로딩이 끝나기 전에 저장하지 않는다. 불러오기 오류 시 자동 저장을 중단하고 오류를 안내한다. 저장 실패 시 편집 결과를 유지하고 재시도 버튼을 제공하며 저장 완료로 표시하지 않는다.
9. 빈 결과, 후보 부족, 유효하지 않은 입력과 저장 오류를 처리한다. 접근 가능한 라벨, 키보드 조작, 읽기 쉬운 스타일을 제공한다.
10. localStorage에 직접 접근하지 말고 저장 모듈만 사용한다. 브라우저 기능은 클라이언트 컴포넌트에서 사용한다. 음원 재생 버튼은 만들지 않는다.

[연동]
- docs/contracts.md의 export와 types/music.ts를 그대로 사용한다. 상대 경로로 import한다.
- 2번 모듈이 아직 없다면 components/dev/ 안에 임시 mock을 두고 UI 구현을 계속한다. 다른 역할 경로에 파일을 만들지 않는다.
- mock 사용 여부를 화면과 완료 보고에 명시한다. 실제 모듈이 준비되면 자기 파일의 import를 바꿔 연동하고 mock을 제거한다.
- 모듈 부재로 연동이 불가능하면 UI 구현과 미연동 항목을 정확히 보고하며 완성됐다고 주장하지 않는다.

기존 실행·타입 검사·빌드 명령이 있으면 수행한다. 테스트를 실행하려고 공동 설정을 바꾸지 마라. 마지막에 담당 변경 파일, 검증 결과, 미연동 항목 및 공동 설정 요청을 보고해라. 계획만 설명하지 말고 허용된 파일에 실제 구현해라.
